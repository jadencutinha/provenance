# Foundry runbook — Phase 1 (Ingest) and the ingest→ontology bridge

You drive Foundry; this is the click-by-click. Steps marked **▶ REPORT BACK** are where I need
what you see so I can finalize the next phase. Your space is `jadencutinha`; your stack has
Pipeline Builder, Ontology Manager, AIP Logic, Workshop, Code Repositories.

Upload-ready files are generated by `./.venv/bin/python scripts/export_foundry.py` into
`data/foundry_upload/`:
- `source_documents.csv` — one row per label (document_id, drug, title, setid, pages, url)
- `document_pages.csv` — one row per page (document_id, page_number, width, height, text)
- `page_words.csv` — one row per word w/ bbox + normalized coords (the anchor coordinate layer)
- `claims_seed.csv` — our 12 verified claims (bootstraps the Ontology before AIP Logic exists)

---

## Step 1 — Create the project
1. Left nav → **Files** → **+ New** (top-right) → **Project**.
2. **Space:** `jadencutinha`. **Template:** **Sandbox project** (instant, fully editable).
3. Name it **`Provenance`** → Create.

## Step 2 — Load the corpus (Media Set = the PDFs the reviewer will display)
1. Inside the Provenance project → **+ New** → **Media Set** → name **`label_pdfs`**.
2. Upload the 5 PDFs from `data/raw_pdfs/` (warfarin, isotretinoin, metformin, clozapine,
   atorvastatin). Confirm 5 documents land.
   - The Media Set is what the app viewer points at to render the real page.

## Step 3 — Get page text + coordinates (the two paths)
We need, per page: **text** (for AIP Logic to read) and **word bounding boxes** (for anchoring).
Two ways — do 3A to showcase AIP, and we rely on 3B as the guaranteed coordinate source.

### 3A — AIP Document Intelligence / OCR (the visible "ingest" moment for the video)
1. Open **Pipeline Builder** → New pipeline in the Provenance project.
2. Add the `label_pdfs` media set as input.
3. Search the transform palette for **"Extract"**, **"OCR"**, **"Parse document"**, or
   **"Document"**. Add the document-text extraction transform. Output a dataset
   `di_pages`.
4. **▶ REPORT BACK:** (a) the exact name of the transform you used, and (b) the **column names**
   of `di_pages` — specifically whether any column carries **position / bounding-box / bbox /
   coordinates** per token. A screenshot of the output schema is perfect.
   - If it has coordinates → we anchor off Document Intelligence directly (cleanest).
   - If it only has text → we use 3B for coordinates. Either way we're unblocked.

### 3B — Upload the coordinate datasets (guaranteed path)
1. In the Provenance project → **+ New** → **Dataset** → **Import** (or drag-drop).
2. Upload from `data/foundry_upload/`: `source_documents.csv`, `document_pages.csv`,
   `page_words.csv`, `claims_seed.csv`. Keep dataset names matching the file names.
3. Confirm row counts: `document_pages` ≈ 240, `page_words` ≈ 76k, `claims_seed` = 12.

## Step 4 — Sanity check
Open `document_pages` and `page_words` in the previewer. Confirm `page_words` has
`x0, top, x1, bottom` (points) and `nx0, ntop, nx1, nbottom` (normalized 0–1) columns.
**▶ REPORT BACK:** confirm this looks right, and paste any column you're unsure about.

## What comes next (so you can see where this leads)
- **P2 (Extract):** paste the prompt + output schema from `docs/EXTRACTION.md` into an **AIP
  Logic** function; run it over `document_pages.text` → a `claims_raw` dataset. Then a Pipeline
  Builder **Python transform** (port of `scripts/anchor_claims.py`) joins `claims_raw` to
  `page_words` → adds `bbox` + `verifiable`.
- **P3 (Ontology):** in **Ontology Manager**, create object types **SourceDocument,
  DocumentPage, Claim, Drug, Condition** backed by these datasets; add links
  `Claim→DocumentPage→SourceDocument`, `Claim→Drug`, `Claim→Condition`; add the
  **Accept/Reject/Flag Action** on Claim (writes `review_status`, `reviewer`, `reviewed_at`).
- **P4 (App):** generate the **OSDK** from the Ontology (Developer Console) and point the
  React reviewer (already being built against the same shapes) at it.

> Shortcut available: because `claims_seed.csv` is real and verified, you can build the entire
> Ontology + reviewer in P3/P4 **now** off the seed, get a working end-to-end demo, then swap
> the seed for AIP-Logic-extracted claims. De-risks the deadline.
